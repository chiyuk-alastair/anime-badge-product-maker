# Security Policy

## Supported versions

Security fixes are applied to the latest version on the `main` branch.

## Reporting a vulnerability

Do not open a public issue for a vulnerability, exposed credential, private customer image, or other sensitive-data incident.

Use GitHub's **Private vulnerability reporting** feature on the repository Security page when available. Include:

- the affected file or workflow;
- the impact;
- reproducible steps that do not expose third-party data;
- a suggested mitigation, if known.

If private vulnerability reporting is unavailable, contact the repository owner through the private contact method shown on their GitHub profile. Do not attach real customer imagery unless the owner explicitly requests it through a secure channel.

The maintainer will acknowledge a complete report when practical, assess severity, and coordinate a fix before public disclosure.

## Scope

Relevant reports include credential exposure, unsafe workflow permissions, unintended publication of private source images, path traversal in repository scripts, or a validation bypass that could ship unintended customer assets.

Content-quality disagreements and ordinary generation defects should use the public issue templates instead.
